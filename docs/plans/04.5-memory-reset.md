# Sub-plan 4.5: Forget memory / reset an account (caregiver UI) + microphone mute

Part of the [master design](00-master-design.md). Depends on [04](04-memory-update.md) (done: memory per account). It's a small step added between 04 and [05](05-next-class-builder.md) at Tomer's request, and an early slice of the caregiver page ([08](08-caregiver-page.md)).

## Goal
Let a caregiver **reset the tutor's memory**, so the app can be demoed from scratch ("first meeting" → "she remembers me" → real progress over sessions), and so Dad's record can start clean before his first real session.

## Also in this step: microphone mute (Tomer's request)
A **"🔇 השתקה"** ("mute") button on the session screen that mutes **only the microphone**, like muting yourself on a call. It isn't a pause:
- The session goes on, she keeps talking, and she still answers what he said last.
- While muted, the client **keeps streaming, but sends pure silence** instead of the mic. Background noise (TV, people talking) can't interrupt her, and Gemini's voice detection still sees the silence after his last words, so it answers normally.
- The live captions ignore the room while muted. The button reads "🎤 החזרת הקול" ("unmute"), the status shows "המיקרופון מושתק" ("the microphone is muted"), and the mic bar greys out. The silence nudge runs as usual. A new session always starts unmuted.
- A first version stopped the stream and sent `audioStreamEnd`. That behaved like a pause, and Tomer rejected it.

## Out of scope
- the memory viewer, rollback to a `memory_history` version, and restore-from-backup in the UI (08)
- editing the patient profile (08)

## Design
- **Who:** caregivers only (`CAREGIVER_EMAILS`).
  - The **"ניהול"** ("admin") link on the start screen is shown only when `/api/me` returns `is_caregiver: true`.
  - **The server enforces it:** `require_caregiver` → 403 for Dad's account, 401 without sign-in.
- **What:** two actions, on **one allowlisted account at a time**:
  - **"שכחי את הזיכרון"** ("forget the memory") deletes `patients/{email}/memory/current`. The next session starts like a first meeting: no recall, empty word bank. Sessions, transcripts and `memory_history` are **kept**.
  - **"מחיקה מלאה"** ("delete everything") is a recursive delete of `patients/{email}`: sessions + turns, memory, memory history and flags.
- **Safety:**
  - Confirm by typing the account's email; the button stays disabled until it matches. The server checks it again (400 otherwise).
  - Only emails on the allowlist can be targeted (404 otherwise), and other accounts are never touched.
  - The memory is **backed up first** as JSON to `gs://heb-practice-private/debug/memory-backups/<email>/<UTC timestamp>-<scope>.json`. The existing `objectCreator` grant covers it, and it falls under the same 30-day expiry as `debug/`. A reset can be undone by hand.
  - Every reset is logged in Cloud Run (`[admin] <caregiver> reset <account> (<scope>)`).

## Files
| File | Purpose |
|---|---|
| `app/main.py` | `GET /api/admin/accounts` (allowlisted accounts with sessions / memory / word counts). `POST /api/admin/reset {email, scope: memory\|everything, confirm_email}`. `/api/me` adds `is_caregiver`. |
| `app/store.py` | `account_overview`, `forget_memory`, `delete_account` (Firestore `recursive_delete`), plus in-memory versions. |
| `app/prompt_archive.py` | `save_backup()`, which writes next to the prompt archive under `debug/memory-backups/`. |
| `static/index.html`, `static/style.css`, `static/app.js` | The "ניהול" link (caregivers only) and the admin screen: account picker + summary, the two choices, typed confirmation, status. |
| `static/index.html`, `static/style.css`, `static/app.js` (mute) | The mute toggle: the capture handler streams zero-filled chunks while muted; the recognizer is ignored; status and mic bar. |
| `tests/test_admin.py` | Caregiver-only (403/401); `is_caregiver`; the overview; forget keeps transcripts and other accounts, and the next prompt has no memory; delete-everything for one account only; confirmation and allowlist checks; backup written first. |
