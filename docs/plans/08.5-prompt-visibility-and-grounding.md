# Sub-plan 8.5: See the tutor's prompt, and stop invented people

Part of the [master design](00-master-design.md). Added between [08](08-caregiver-page.md) and [09](09-polish.md) at Tomer's request (2026-10-06).

## Why: what went wrong in the session on 6.10.26, 13:31 (Tomer's account)
The tutor asked Tomer about people who don't exist ("the friend who advises you on tech and home repairs", "the family member who organises the holidays… רונית"). When he said he didn't know them, she gave the "answer" anyway ("התכוונתי לרונית"). The cause was a chain of four failures:
1. **The planner notes** asked for family and friends' names only, but his memory held just one real person (his wife).
2. **The plan builder invented the answers to fill the plan:** check-ins דני, מיכל, אבי and practice items יוסי, רונית, each with an invented story. This broke the prompt rule "don't invent his family". The last three plans were all built by the smallest fallback model (`3.5-flash-lite`), because the free daily quota of the stronger models was used up, and that model ignores such rules most easily.
3. **The tutor followed the plan too faithfully.** Nothing told her what to do when he says a person doesn't exist.
4. **The invented names stayed in the data.** The memory update recorded them in the **word bank** as "failed", due for practice again.

## Decision: no separate "LLM as a judge"
- A judge reviewing the session **after** it happened sees the problem too late. This one starts in the **plan**, before the session, and can be blocked **in code**.
- The memory update **already reads every transcript with a model**. One more tool there (`report_tutor_issue`) gives the same "something went wrong" signal at no extra model call.
- No automatic prompt rewriting. A prompt changing itself with no review is riskier than the problems it fixes. Flags point Tomer to the sessions to look at, and prompt changes stay deliberate.
- Free-tier quota is already the limit (see 2. above). Another model call per session would make that worse.

## Scope
1. **See the prompts** on the caregiver page:
   - **Per session:** a "הפרומפט" ("the prompt") button next to "תמלול מלא" ("full transcript") shows the exact system instruction the tutor got in that session.
   - **Next session:** a section "הפרומפט לשיחה הבאה" ("the prompt for the next session") shows the full instruction the tutor would get if the next session started now, built by the **same code** as the session start.
2. **Grounding guard (code), in the plan builder:** a check-in or practice item **about his own life** is kept only if its answer can be found in his own data. Otherwise it's dropped, and the plan is rejected if it becomes too thin (the existing rules).
   - **"About his life"** (both checks are used):
     - the model marks it, with a new `about_his_life` field on each item
     - **or** the question or lead-in addresses him personally (שלך / איתך / אליך / אצלך / שלכם…)
   - **"His own data":** the memory (summary + sections), the profile, the planner notes, and **his own lines** in the last 3 transcripts (a name he said himself counts, whatever language the memory stores it in). **Not** the word bank (see the notes below).
   - **Not affected:** general items (well-known places, public figures).
3. **Builder prompt:** when the memory has few names of his people, the session **collects** names through conversation (as in the intro) instead of quizzing him on names nobody knows. The plan never invents people, events or relationships.
4. **Memory-update prompt:** names of people and places are written in **Hebrew letters** (English in parentheses is fine), so the guard and the word bank match them.
5. **Tutor rule (`tutor.yaml`):** for questions about his own life, if he says he doesn't know the person or place, or that it isn't true, she **believes him**, says briefly that she must have mixed something up, and moves on. She never supplies or insists on an "answer" about his own life.
6. **Tutor-mistake flags:** a new tool in the memory update's tool phase, `report_tutor_issue(kind, evidence)`.
   - **Kinds:**
     - `invented_fact`: she stated or asked about something not in his life
     - `insisted`: she pushed an answer he rejected
     - `wrong_language`: not Hebrew
     - `cut_off`: interrupted him
     - `other`
   - It's saved as a low-severity flag `tutor_issue` and shown on the caregiver page (it doesn't alarm like a health flag) with its evidence quote.
7. **Word-bank cleanup:**
   - An ✕ on each word-bank row on the caregiver page (backup first, as with other memory edits).
   - Remove דני, מיכל, רונית and אבי from Tomer's word bank, using that ✕.

## Notes from building it
- **The first dry run let the invented names through.** The guard counted the **word bank** as "his data", and the word bank still held דני / מיכל / רונית / אבי from the 6.10 session. The builder's context even listed them as "due for practice today". So:
  - **The word bank is no longer proof:** a word there only means the tutor practised it.
  - **The memory update must not call `record_word_result`** for an item he says isn't part of his life; it reports a tutor issue instead.
  - **Cleaning the word bank** (task 1) is what removes the "due today" bait.
- **One retry with feedback.** If the guard drops invented items and the plan becomes too thin, the builder gets one more try, told exactly which names were invented. In the dry run (Tomer's memory, the "family names only" note, words cleaned) the first try invented שרה and "חבר מהצבא". The retry produced check-ins on places from his memory and an activity that collects the names of his people.
- **Priority rule in the builder prompt:** never invent > the notes > everything else. When the notes ask for more than his data has, it uses what's known, collects the rest in the activity, and says so. The weak model still wrote a too-rosy `notes_applied` ("avoids all place names") — which is why the page labels it as the builder's own account.
- **Hebrew prefixes:** "גרתי ברמת גן" counts for "רמת גן". The match allows up to two prefix letters (ב, ה, ו, ל, מ, ש, כ), and ignores vowel marks and punctuation.
- **Names in Hebrew letters:** the memory had "his wife Shira" in English while he said "שיר". The memory update now writes names in Hebrew letters.
- **Retry cap:** a failed plan used to be retried by the hourly sweep forever (2–3 model calls each time). Now `plan_attempts` stops it after 3 automatic attempts; the rebuild button still works.
- **Readable tutor-issue flags** (Tomer's request): the tool fills separate fields (`tutor_said`, `he_said` in Hebrew; `what_went_wrong` in English) and the page puts each on its own line. General rule in the memory-update prompt: never an English and a Hebrew sentence in one line. In Tomer's first session after 8.5, two flags caught real mistakes: his wife's name ("שירה" instead of "שיר"), and an invented story about trips to Eilat.
- **Model quality:** all the dry runs, and the 6.10 plan, used `3.5-flash-lite`, because the stronger models' free daily quota was used up. The paid tier would avoid that.
